## Download

**[r7z-0.1.1-windows-x64.zip](https://github.com/hdunl/r7z/releases/download/v0.1.1/r7z-0.1.1-windows-x64.zip)** contains both programs. Unzip it anywhere, no installer needed.

| File | What it is |
|---|---|
| `r7z-gui.exe` | The desktop app |
| `r7z.exe` | The command line tool, with 7-Zip's commands and switches |
| `r7z_shell.dll`, `package\` | The Windows 11 context menu |

Windows 10 or 11, 64-bit.

## What changed

**Security**
- Every dependency is on its current release, with no known advisories. Two unmaintained
  crates that came in through the font renderer and the file dialogs are gone.
- The updater now talks to GitHub through Windows' own TLS and certificate store.
- The AES code no longer needs an `unsafe` block.
- Archive parsing and damaged-archive recovery are now fuzzed continuously.

**Releases you can verify**
- SLSA build provenance (`.intoto.jsonl`) and a Sigstore bundle (`.sigstore.json`) are
  attached to every release, alongside the existing `SHA256SUMS` and signed update manifest.
- Both programs now carry version information in their file properties.

**Explorer**
- r7z can now appear in Windows 11's main right-click menu as an **r7z** submenu. Windows
  only accepts this from signed packages; until r7z releases are code-signed it works
  with Developer Mode on (Settings → Explorer menu). The classic entries under
  "Show more options" work everywhere, as before.
- Extract here and Extract to work on several selected archives at once.

**Fixes**
- Text in input fields is vertically centered again.
- Crashes found by fuzzing, all integer overflows on crafted archive headers: WIM sizes,
  tar sparse maps and pax times, zip recovery sizes, recovery offsets and timestamps.
  Out-of-range timestamps also no longer stop an extraction.

## Verify your download

```
gh attestation verify r7z-0.1.1-windows-x64.zip --repo hdunl/r7z
```

Or offline, with the bundle from this page:

```
gh attestation verify r7z-0.1.1-windows-x64.zip --bundle r7z-0.1.1.sigstore.json --repo hdunl/r7z
```

The programs are not code-signed yet, so Windows SmartScreen may ask for confirmation the
first time; choose **More info → Run anyway**.
